# onboarding

The full-screen flow that welcomes a learner, and that Profile reopens in parts. Also the learner's name and hometown as the stories and the tutor use them. No tab, no server half: it saves through the progress document.

| | |
|---|---|
| Deep link | `onb`: `/onboarding` (and the old `#onb`) opens the full flow (`WebFeature.open.onb`, a dev screen) |
| Modes | `full` (a new learner: Escape and the browser back don't close it; it is not on the overlay stack), `update` (an existing learner, once, when `S.onb < ONB_V`: what's new, the character), `edit` (name, character, hometown), `place` (Profile's *Retake placement*: the only place the level is chosen). `ORDER` in `model/flow.ts` lists the steps. A new learner's flow is about the stories: no level or path step |
| Steps | One choice per screen, a progress bar at the top, Back and Next at the bottom (`Flow.tsx`: `StepView`, `Nav`, `Quiet`). `steps/Lang.tsx` (the help language: English, فارسی, Русский; saved as `prefs.lang`, and the flow speaks it from then on, Persian right to left), `Name.tsx`, `Character.tsx` (five steps, one per section of the builder: below), `Home.tsx` (the hometown, typed or one tap; the tutor's clean form when it can, else as typed; job, hobby and why stay empty), `Rest.tsx` (what's new, class, the daily reminder about the stories, the cast, which ends on "Read your first story": the Stories tab's next story), `Place.tsx` (`place` mode only: self-report, the quiz from the placement feature, the writing sample, the suggested start). The answers live in one object in `Onboarding.tsx`, so Back finds them again; a step that throws while drawing is caught there (`useErrorBoundary`) and offers Next |
| Overlay | `open.ts`: `openOnboarding(mode)` makes the `.onb-back` dialog on the body, puts it on the overlay stack (except `full`) and mounts the flow; closing saves `S.onb = ONB_V` and flushes the invite links that waited (`ui/later.ts`). `maybeOnboard()` is the boot's offer (not on `/connect/yeni`; waits for progress). If the flow's chunk does not load, the first time in a tab it loads the current version (`host.update()`: a waiting service worker takes over, else a reload), because the usual cause is a page from before a deploy asking for a chunk the server no longer has (the Worker answers it with the page, which `app/host/swcache.ts` keeps out of the caches). After that the dialog says so (Try again, Go to the app) and `S.onb` is left alone, so the next visit offers it again. No regex lookbehind in this feature: Safari before 16.4 cannot parse one, and the Stories tab imports its chunk too |
| Model | `model/flow.ts` (modes, step order, the character steps, the classes offered), `model/version.ts` (`ONB_V` alone: `open.ts` is in the entry chunk), `model/answers.ts` (`initAnswers`: what the flow starts from, safe on any saved shape), `model/words.ts` (the flow's words in English, Persian and Russian, `uiLangOf`, `guessLang`), `model/names.ts` (`nameSuffix`: Turkish endings in vowel harmony, `cap`, `hasFa`, `translitOffline`), `model/profile.ts` (`CITIES`, `cityLookup`, `profileFallback`, `normProfile`), `model/personalize.ts` (the Nima / Tahran swap: the stories' newcomer becomes the learner, the tutor's blurb). `personalize.ts` fills these with the learner's name and profile from the page state. Tested by `scripts/kumru_onb.test.cjs` and `model/answers.test.ts` |
| CSS | `onboarding.css` (`onb-*`, `av-*`, `nm-in`; `.onb-back [lang=tr]` stays left to right in a Persian flow); the quiz's is `placement.css` |
| Storage | `S.nick`, `S.char`, `S.profile`, `S.onb`, `S.placed` (progress document); `kumru:pending-class` (read: an invite waiting skips the class step) |

Other features' parts: the tutor (`tutor`: `translitName`, `buildProfile`, `checkPlacement`, `seedPlacementMistakes`, `aiState`, `aiErrText`; it calls back `learnerBlurb`, `translitOffline`, `profileFallback`, `normProfile` from this feature's `index.ts`), the quiz (`placement`: `loadClimb`, `applyPlacement`, `PL_SELF`, `plNudge`), the class step (`classes`: `classes.list/join`), the reminder step (`reminders`: `remindStep`, `loadRemindBody`), the help language (`profile`: `setPref`), the first story (`stories`: `openStory`, `loadStories`, `nextStory`), `ui/Seg`, `ui/TypeAids` (Turkish letters, mic), `ui/Portrait`, `ui/Pup`.

## Boot and names

- `maybeOnboard()` at the `routed` phase, once the learner and their progress are known and the first deep link has opened.
- `studentName()` (through `ui/avatar`'s `setLearnerName`) and `personalizeStr()`.
- `personalize()` (a whole story document) is unused until the Sahne stories need it; the test covers it.

## Character

The five character steps mount Sahne's builder once from the lazy `builder` bundle (`app/lib/builder.ts`: learner mode, the kit's starter set with "More", the `base` set family for the wall, `builds: ["adult"]`, `tabs: false`, `moods: false`) and keep it in the flow's answers: each step moves the builder's element into its frame and calls `setSection` (body, face, hair, clothes, extras), so the live preview stays on top, frames what is being chosen (a hat, the shoes), and undo and Back keep the character. "Start over" asks through `confirmAsk` (`app/ui/sheet.ts`). Every step saves the character, normalized as untrusted and made an adult (`storable`). A slow load keeps waiting and after 8 s offers "Skip the character for now"; a load that fails, or that skip, leaves out the other character steps (the character is made later from Profile). The builder's own labels are the kit's English. Portraits draw through `app/ui/avatar` (`chAvatar`, `Avatar`). `index.ts` gives it the learner's name (`setLearnerName(studentName)`) for the stand-in. The cast step shows Kerim and the first Season 1 cast heads from `cast.gen.ts` (written by `scripts/avatar-art.ts` from `data/characters`: the characters listed in its `ONBOARDING_CAST`; imported only here, so the SVGs stay out of the entry chunk).
